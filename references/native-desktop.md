# 原生程序、.NET、Go 与其他桌面程序

## 原生程序（C、C++、Rust、Swift 等）

- 发布版去除符号和调试信息，调试符号只保存在内部或崩溃上报平台：
  - GCC、Clang：发布构建不带 `-g`，链接后执行 `strip`；共享库用 `-fvisibility=hidden`，只导出必要符号。
  - MSVC：PDB 只保留在内部符号服务器，不随安装包发布。
  - Xcode：开启 `STRIP_INSTALLED_PRODUCT`，dSYM 只上传到崩溃上报平台。
  - Rust：在 `[profile.release]` 中设置 `strip = true`。
- 删除描述内部逻辑的日志、断言信息和错误字符串。分析者通常最先看字符串。
- 开启优化（`-O2` 及以上）和 LTO。反编译出的伪代码会更难读，程序性能也更好。
- 不要把密钥和内部地址硬编码在程序里，字符串加密只能拖延片刻。

## 授权与付费

- 授权以服务端在线校验为主：激活、续期以及付费功能需要的内容或能力，都由服务端下发。
- 离线授权文件使用非对称签名，客户端只放公钥。这样别人无法伪造授权文件，但仍要接受客户端本身可能被修改。
- 不要让本地一个"是否付费"的布尔判断决定全部功能。

## .NET

- 普通方式发布的程序集包含完整 IL，可以反编译到接近源码。
- 条件允许时使用 NativeAOT（`<PublishAot>true</PublishAot>`）编译为原生代码，IL 反编译器拿不到方法体，分析者只能做原生分析。ReadyToRun 仍然保留 IL，不算保护。
- 不能用 NativeAOT 时，用 .NET 混淆器（改名、控制流混淆）作为减速带。
- 发布目录里不要带 `.pdb`。

## Go

- 发布构建使用 `go build -trimpath -ldflags="-s -w"`，去掉本地路径、符号表和调试信息。
- 不想公开版本控制信息时，加 `-buildvcs=false`。
- 依赖模块列表仍会嵌在程序里（`go version -m <程序>` 可以查看），编译参数去不掉，要接受它公开。

## Java 桌面程序

- JAR 里的字节码很容易反编译。可以用 ProGuard 或 R8 混淆，或用 GraalVM Native Image 编译为原生程序。

## Python 打包程序（PyInstaller 等）

- 打包进去的字节码可以被还原，核心逻辑应放在服务端。需要拖延时，可以把关键模块用 Cython 或 Nuitka 编译成原生扩展。

## 商业加固

- 代码虚拟化、商业保护壳只值得用在高价值客户端，例如游戏、版权保护、金融类应用。
- 代价包括性能下降、兼容性问题和杀毒软件误报，而且只能拖延时间。决定之前，先确认架构层的措施都已做完。
